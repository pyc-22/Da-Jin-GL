# 打金店管理系统打包发布计划书

## 1. 目标

本计划用于生成一套可安装、可部署、可回滚的正式发布包，覆盖：

- 服务端：Spring Boot、MySQL、Redis、MinIO、管理端 H5、移动端 H5。
- 收银端：Windows x64 Electron 安装包。
- 移动端：H5/PWA；Android APK 在原生构建链验收后生成。
- 交付资料：配置模板、部署说明、测试报告、版本说明、校验文件和回滚说明。

首个正式候选版本建议使用 `V1.0.0-rc.1`，通过门店验收后发布 `V1.0.0`。

## 2. 当前构建条件

| 模块 | 当前构建方式 | 计划产物 | 状态 |
|---|---|---|---|
| 后端 | Maven + Java 17 | `backend-1.0.0.jar`、Docker 镜像 | 可执行 |
| 管理端 | Vue3 + Vite | `dist/`、Nginx Docker 镜像 | 可执行 |
| 收银端 | Vue3 + Electron Builder | Windows NSIS 安装程序 | 可执行 |
| 移动端 H5 | Vue3 + Vite | `dist/build/h5/`、Nginx Docker 镜像 | 可执行 |
| 移动端 APK/IPA | HBuilderX/uni-app 原生构建 | APK/IPA | 需先验证原生构建链 |
| 基础设施 | Docker Compose | MySQL、Redis、MinIO、Web 服务 | 可执行 |

移动端目前由普通 Vite 和 `vue-router` 启动，虽然已有 `manifest.json`、`pages.json` 和部分 `uni.*` 调用，但 `package.json` 尚未配置完整的 `@dcloudio` 原生编译依赖。因此本次应先交付 H5；APK 作为单独里程碑，在扫码、相机、文件上传、拨号和原生路由完成真机验证后纳入正式包。

## 4. 发布前门槛

### 4.1 功能冻结

- 建立发布版本号，不再合入非必要功能。
- 固定数据库结构、权限编码和 WebSocket 消息格式。
- 确认销售默认权限包含入库盘点、回收、加工和会员。
- 确认管理端、收银端、移动端使用同一套接口版本。

### 4.2 生产数据清理

当前 `db/schema.sql` 含演示账号、演示商品、演示金价和默认密码。正式包应拆分为：

- `schema.sql`：仅表、索引和基础角色权限。
- `bootstrap.sql`：必要的门店、角色、支付渠道、基础分类。
- `demo-data.sql`：演示账号和示例商品，只进入测试包，不进入生产包。

生产环境首次启动时创建独立管理员账号并强制修改初始密码。历史业务数据通过备份恢复，不打入安装包。

生产登录界面还必须完成以下清理，否则不得生成正式版：

- 收银端删除“演示环境账号：admin，密码：admin”提示。
- 移动端删除“演示账号：admin / admin”提示，并清空账号、密码默认值。
- 管理端清空预填的 `admin/admin`，账号和密码输入框默认保持为空。
- 清理已生成的旧 `dist`、Electron `release` 和 Docker 前端镜像，避免旧提示继续留在发布产物中。
- 构建完成后同时扫描源代码和发布产物，确认不存在演示账号、默认密码、测试账号提示或硬编码登录凭据。

### 4.3 配置冻结

- 生成不少于 32 字节的随机 `JWT_SECRET`。
- 分别设置 MySQL、Redis、MinIO 强密码。
- 配置正式域名、HTTPS、CORS、MinIO 外部访问地址。
- 生产服务器只开放 `80/443`，管理端口仅允许内网访问。
- 收银端和移动端 API 地址指向正式 HTTPS 网关，不写死局域网开发地址。

## 5. 测试与质量门禁

打包前必须全部通过：

1. 后端：`mvnw.cmd -pl backend test`。
2. 管理端：`pnpm test`、`pnpm build`。
3. 收银端：`pnpm test`、`pnpm run build`。
4. 移动端：`pnpm test`、`pnpm run build:h5`。
5. Docker：所有服务达到 `healthy`，`minio-init` 为 `Exited (0)`。
6. 业务冒烟：登录、商品改价实时同步、入库、盘点、开单占库、收款扣库、会员刷新、回收、加工、图片上传、报表权限。
7. 角色回归：管理员、店长、前台、销售分别验证菜单、接口和数据范围。
8. 并发回归：库存剩余 1 件时，只允许一个待收款订单占用并完成结算。
9. 断网回归：移动端入库草稿、照片路径和待同步队列恢复正常。
10. 恢复演练：用生产候选备份执行一次完整恢复并核对订单、图片和权限。
11. 登录页检查：三个客户端不展示演示账号，不预填账号密码，安装包及压缩资源中不存在 `admin/admin` 提示。

任一 P0/P1 缺陷未关闭时停止生成正式版，只生成测试候选包。

## 6. 构建顺序

### 6.1 后端

```powershell
.\mvnw.cmd -pl backend clean test package
```

校验 `backend/target/backend-0.1.0.jar` 可启动，健康接口返回 `UP`，再复制到发布目录并按正式版本命名。

### 6.2 管理端

```powershell
Set-Location admin-web
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

检查登录、路由刷新、静态资源、API 代理和 WebSocket 代理。

### 6.3 移动端 H5

```powershell
Set-Location mobile
$env:VITE_API_BASE='https://api.example.com'
pnpm install --frozen-lockfile
pnpm test
pnpm run build:h5
```

产物为 `mobile/dist/build/h5`。使用真机浏览器验证安全区、日期选择、弹窗、底部 Tab、扫码降级提示和图片上传。

### 6.4 收银端 Windows 安装包

```powershell
Set-Location front-pc
pnpm install --frozen-lockfile
pnpm test
pnpm run dist
```

在一台未安装开发环境的 Windows 10/11 电脑执行安装测试，核对 API 配置持久化、自动更新策略、扫码枪、58/80mm 小票、A4 质保单和卸载流程。

### 6.5 Docker 服务端包

```powershell
docker compose build --pull backend admin-web mobile-web
docker compose up -d
docker compose ps
```

使用固定版本镜像标签，不在正式版长期使用 `latest`。首次启动和旧库升级各执行一次验证。

### 6.6 Android 原生包

1. 完成 uni-app 原生构建依赖和入口适配。
2. 配置正式 AppID、包名、版本号、图标、启动图和 Android 签名。
3. 真机验证二维码扫码、拍照、相册、本地缓存、上传、拨号、WebSocket 重连和后台恢复。
4. 生成签名 APK，记录证书指纹和 SHA-256；签名文件单独保管，不进入发布包。

## 7. 发布验证

测试环境部署候选包后执行以下验收：

- 服务健康、数据库迁移、MinIO bucket、Redis连接均正常。
- 管理端修改商品、金价、会员和员工权限后，其他端实时同步。
- 销售账号显示入库盘点、回收、加工、会员；无盘点审批权限。
- 前台能接收移动端开单和加工打印任务。
- 图片 URL 在管理端、收银端、移动端均可访问。
- 重启全部容器后业务数据、图片和离线队列仍存在。
- 日志不包含密码、Token、身份证号和完整敏感请求体。

验收通过后，将候选版提升为正式版，只修改版本号和发布说明，不重新修改业务代码。

## 8. 上线步骤

1. 通知门店进入维护窗口，停止新增订单和入库操作。
2. 备份 MySQL、MinIO、上传目录、`.env` 和当前 Docker 镜像标签。
3. 校验备份可读取，并记录当前版本和容器状态。
4. 上传发布包，替换程序文件，不覆盖生产 `.env` 和数据目录。
5. 执行 `docker compose up -d --build`。
6. 等待健康检查通过，执行管理员、店长、前台、销售四角色冒烟测试。
7. 安装或升级收银端，验证打印机和待收款订单。
8. 开放业务，观察日志、错误率、WebSocket连接和库存流水至少 30 分钟。

## 9. 回滚方案

触发条件：无法登录、库存异常扣减、订单无法结算、数据库迁移失败、图片大面积不可访问或 P0 数据越权。

回滚步骤：

1. 立即停止新业务写入。
2. 将 Docker 镜像和前端目录切回上一正式版本。
3. 若数据库只发生兼容性新增字段，可保留数据库并回滚应用。
4. 若存在破坏性数据变更，先恢复上线前备份，再启动上一版本。
5. 收银端使用上一版本安装包覆盖安装，确认本地待同步数据已导出。
6. 完成登录、库存、订单和图片检查后恢复营业。

## 11. 发布完成标准

- 所有制品版本号一致，SHA-256 校验通过。
- 自动测试和核心业务验收全部通过，无未关闭 P0/P1。
- 生产包不含演示数据、真实密码、日志、备份和旧制品。
- 管理端、收银端、移动端登录页均不展示或预填演示账号密码。
- 部署、备份、恢复、安装、打印和回滚文档齐全。
- 管理端、收银端、移动端、后端和 WebSocket 使用同一正式环境。
- 上线后监控期内无库存、支付、权限、图片或同步异常。
