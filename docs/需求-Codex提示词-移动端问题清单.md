## 问题 1：员工排行榜显示"暂无数据"，但经营报表里能看到员工销售排行

- **现象**：手机端首页的员工排行榜是空的；进入「经营报表」却能看到员工销售排行数据。
- **期望**：**同一时间段、同一权限**下，首页排行榜与经营报表的员工排行数据一致（首页显示前 3~5 名 + 「查看全部」）。
- **定位线索**：
  - 首页（`views/RoleHome.vue` 的 manager 区块）与报表页（`views/ReportDashboard.vue`）分别调用了哪个接口/字段？很可能是**首页用的接口/参数不同**（时间范围、`employeeId`、权限 `report:commission`/`report:store-performance`）或**取错了字段名**（如 `employees` / `overview.employees` / `summary.*`）；
  - 检查空态是否把"接口报错"也显示成"暂无数据"（应区分：无数据 vs 加载失败 + 重试）。
- **验收**：生产/本地有销售或加工数据的账号登录后，首页排行榜能显示员工与金额；无数据时提示"暂无数据"，接口失败时提示失败并可重试。

## 问题 2：加工订单里"已取货"的单可以右划删除

- **现象**：加工订单列表中，客户已取货（`PICKED_UP`）的单仍能右划删除。
- **期望**：**已取货的单不允许右划删除**（避免误删已交付单据）。如仍需要清理列表，请给"归档"入口并**二次确认**，文案明确「管理端仍保留完整记录」；其他状态（待加工/加工中/待取货）的右划删除也要**二次确认**。
- **定位线索**：`views/ProcessingOrders.vue` 的滑动删除/归档逻辑（`mobile_archived`），判断条件里应加状态限制；确认后端 `POST /api/processing/orders/{id}/archive` 是否也需要状态校验（**如需要请先说明，不要擅自改后端**）。
- **验收**：已取货单右划无删除/归档入口（或点了有明确拒绝提示）；其他状态删除前有确认框；管理端记录不受影响。

## 问题 3：消息通知右划，划一条所有消息都跟着右划

- **现象**：在「消息」里右划任意一条，**整个列表所有行一起位移**。
- **期望**：只有被划的那一行位移；再划别的行时上一行自动复位。
- **定位线索**：`views/Notifications.vue` 目前用的是**单个** `offset` ref（所有行共用）；请改成按行保存（参考 `views/home/DocumentsSection.vue` 的 `swipeKey` + `swipeOffset` 写法）。
- **验收**：右划第 2 条 → 只有第 2 条位移；右划第 3 条 → 第 2 条复位、只有第 3 条位移；一条也没划时全部复位。

## 问题 4：金价设置里管理端已禁用的金属，移动端仍能设置金额

- **现象**：管理端把某金属品种停用后，手机端「金价设置」里仍能给它填价格/保存。
- **期望**：手机端只显示**启用中**的品种，或对停用品种**禁止输入/保存**（并给出"该品种已在管理端停用"的提示）；若服务端也接受该品种，请在回复里说明（**不要擅自改后端**）。
- **定位线索**：`views/GoldSettings.vue` 拉取品种列表时是否过滤 `status=1`（含"基准品种/金类配置"两个下拉）；保存前是否校验所选品种仍启用。
- **验收**：管理端停用某品种 → 刷新手机端：该品种不出现（或输入框禁用 + 提示）；停用后再保存不会写入金额。

## 问题 5：货品查询——最近搜索下面没有逐条显示货品；点商品除了生成海报还应能"直接开单"

- **现象 A**："最近搜索"下面**没有列出一个个货品**（列表为空或没渲染）。
- **期望 A**：最近搜索下面逐条显示货品（名称、条码、库存、价格），可点击进入详情。
- **现象 B**：点击商品后只能生成营销海报，**没有"直接开单"**。
- **期望 B**：点击商品（或长按/操作菜单）提供两个动作：**生成营销海报** 与 **直接开单**；"直接开单"跳到销售开单并把该商品带入（按件商品数量默认 1；按克商品提示输入克重；库存为 0 时禁止并提示）。
- **定位线索**：`views/GoodsSearch.vue`（最近搜索的历史列表、点击后的动作菜单）、`views/GoodsDetail.vue`（详情页动作按钮）、开单入口（`views/RoleHome.vue` 的销售开单 / `views/home/SalesOrderSection.vue`）。
- **验收**：搜索 → 列表逐条出现；点商品能生成海报；点"直接开单"能带着该商品进入开单界面并完成下单（含库存/权限校验）。

## 问题 6：首页 KPI（销售克重 / 今日订单数 / 回收克重）恒为 0，且口径没算加工单的补金与剩余金

- **现象**：首页这几个数字**即使有业务数据也显示 0**。
- **期望（第一步：先修数据源）**：有数据时必须显示真实值；无数据时显示 0 并保留空态说明；接口失败要有提示与重试。
- **口径（第二步：老板已给的方向，请按此实现并在标签上写清楚）**：
  - **今日订单数**：= 当日**销售单数 + 加工单数**（建议标签写「今日订单（销售+加工）」，或分开显示两个数）；
  - **销售克重**：= 当日销售单克重 **+ 加工单的补金克重**（`processing_order.store_gold_weight`，即店里卖出的金料）—— 标签写「销售克重（含加工补金）」；
  - **回收克重**：= 当日回收单克重 **+ 加工单的回收屑/剩余金克重**（`processing_order.residual_gold_weight`，即客户旧料剩余）—— 标签写「回收克重（含加工剩余金）」；
  - 所有统计都要排除撤回单（`WITHDRAWN`）与软删除会员；日期按 `Asia/Shanghai` 的"今天"。
- **定位线索**：首页 KPI 的数据来自哪个接口/字段（很可能字段名不符、时间范围参数缺失、或接口没返回这几项 → 需要后端补字段）；先确认"接口到底返回了什么"，再决定是前端取错还是后端没给。
- **验收**：造 1 张销售单 + 1 张带补金/回收屑的加工单 + 1 张回收单，首页三个数字都能对上（给出具体数字核对过程）。

## 问题 7：每进入一个页面，返回都回到首页

- **现象**：从首页进入任意页面（加工订单、单据、消息、报表…），点左上角返回，**都跳回首页**，而不是回到上一层。
- **期望**：按**层级**返回：首页 → 加工订单列表 → 加工单详情；在详情点返回应回到**加工订单列表**，再点返回才回首页。消息/报表/单据等同样处理。
- **定位线索**：`components/DesignHeader.vue` 的 `@back` 处理（是否写死 `router.push('/')` 或依赖不存在的 history）、`views/RoleHome.vue` 的 `section` 状态（是否每次返回都重置为 `home`/`dashboard`）、路由表 `main.js` 中同一组件复用导致 history 不增长。
- **验收**：列出 3 条真实路径逐条验证：
  1. 首页 → 加工订单 → 详情 → 返回=加工列表 → 返回=首页
  2. 首页 → 单据 → 某单据 → 返回=单据列表 → 返回=首页
  3. 首页 → 经营报表 → 员工排行 → 返回=经营报表 → 返回=首页
  安卓物理返回键（若支持）行为应与页面按钮一致。
