## 问题 1：员工排行榜显示"暂无数据"，但经营报表里能看到员工销售排行

- **现象**：手机端首页的员工排行榜是空的；进入「经营报表」却能看到员工销售排行数据。
- **期望**：**同一时间段、同一权限**下，首页排行榜与经营报表的员工排行数据一致（首页显示前 3~5 名 + 「查看全部」）。
- **定位线索**：
  - 首页（`views/RoleHome.vue` 的 manager 区块）与报表页（`views/ReportDashboard.vue`）分别调用了哪个接口/字段？很可能是**首页用的接口/参数不同**（时间范围、`employeeId`、权限 `report:commission`/`report:store-performance`）或**取错了字段名**（如 `employees` / `overview.employees` / `summary.*`）；
  - 检查空态是否把"接口报错"也显示成"暂无数据"（应区分：无数据 vs 加载失败 + 重试）。
- **验收**：生产/本地有销售或加工数据的账号登录后，首页排行榜能显示员工与金额；无数据时提示"暂无数据"，接口失败时提示失败并可重试。

## 问题 2：加工订单里，未取货的单也能右划删除（应只有"已取货"可删）

- **现象**：加工订单列表中，**未取货**的单（待加工 `PENDING` / 加工中 `PROCESSING` / 已完工待取货 `COMPLETED`）也能右划删除。
- **期望（老板明确要求，别写反）**：
  - **只有已取货（`PICKED_UP`）的单可以右划删除** —— 删除 = 手机端归档（列表不再显示），**管理端始终保留完整记录**；
  - **未取货的单一律不允许右划删除**（`PENDING` / `PROCESSING` / `COMPLETED` 都不给右划删除入口；若用户操作到要给出明确拒绝提示）；
  - 已取货单删除前建议**二次确认**（防误删），文案写明「管理端仍保留记录」。
- **定位线索**：`views/ProcessingOrders.vue` 的滑动删除/归档逻辑（`mobile_archived`）目前**没有按状态限制**；请加 `status === 'PICKED_UP'` 判断。确认后端 `POST /api/processing/orders/{id}/archive` 是否也需要状态校验（**如需要请先说明，不要擅自改后端**）。
- **验收**：
  1. 待加工 / 加工中 / 待取货的单右划 → **没有删除入口**（或点了明确提示"未取货不能删除"）；
  2. 已取货的单右划 → 可删除（有二次确认），删除后手机端列表不再显示；
  3. 删除后登录管理端 → 该单**仍在**加工单列表/详情里可见。

## 问题 3：消息通知右划，划一条所有消息都跟着右划

- **现象**：在「消息」里右划任意一条，**整个列表所有行一起位移**。
- **期望**：只有被划的那一行位移；再划别的行时上一行自动复位。
- **定位线索**：`views/Notifications.vue` 目前用的是**单个** `offset` ref（所有行共用）；请改成按行保存（参考 `views/home/DocumentsSection.vue` 的 `swipeKey` + `swipeOffset` 写法）。
- **验收**：右划第 2 条 → 只有第 2 条位移；右划第 3 条 → 第 2 条复位、只有第 3 条位移；一条也没划时全部复位。

## 问题 4：金价设置里管理端已禁用的金属，移动端仍能设置金额

- **现象**：管理端把某金属品种停用后，手机端「金价设置」里仍能给它填价格/保存。
- **期望（老板明确要求）**：**未启用的金属在手机端不显示**（金价设置里根本看不到、也填不了）；**启用/停用不在金价设置里做** —— 启停统一放在**单独的"金类启用/禁用"页面**（管理端已有的金类管理页；如手机端也需要，则单独开一个页面，不要混在金价设置里）。
- **定位线索**：`views/GoldSettings.vue` 拉取品种列表时是否过滤 `status=1`（含"基准品种/金类配置"两个下拉）；保存前是否校验所选品种仍启用；手机端是否有启停开关需要移除/迁移。
- **验收**：管理端停用某品种 → 刷新手机端「金价设置」：**该品种不出现**；启停操作只在单独的启用/禁用页面（或管理端）进行；停用品种无法通过手机端写入金额。

## 问题 5：货品查询——最近搜索下面没有逐条显示货品；点商品除了生成海报还应能"直接开单"

- **现象 B**：点击商品后只能生成营销海报，**没有"直接开单"**。
- **期望 B（老板明确要求）**：
  - **点击卡片 → 进入商品详情**（不是长按，也**不要用长按交互**）；
  - **在详情页**提供两个动作按钮：**生成营销海报** 与 **直接开单**；
  - "直接开单"跳到销售开单并把该商品带入（按件商品数量默认 1；按克商品提示输入克重；库存为 0 时禁止并提示"库存不足"）。
- **定位线索**：`views/GoodsSearch.vue`（最近搜索的历史列表：当前为什么为空、是否渲染成网格、点击后走哪里）、`views/GoodsDetail.vue`（详情页动作按钮，当前只有海报）、开单入口（`views/RoleHome.vue` 的销售开单 / `views/home/SalesOrderSection.vue` 如何接收带入的商品）。
- **验收**：搜索 → 结果与"最近搜索"都按**网格（每行 2~3 个）逐条**出现；点卡片进详情；详情里能生成海报、能"直接开单"并带着该商品完成下单（含库存/权限校验）；**全程不需要长按**。

## 问题 6：首页 KPI（销售克重 / 今日订单数 / 回收克重）恒为 0，且口径没算加工单的补金与剩余金

- **现象**：首页这几个数字**即使有业务数据也显示 0**。
- **期望（第一步：先修数据源，老板原话）**：**有数据时必须显示真实值；无数据时显示 0**（不要用"暂无数据"覆盖 0）；**接口失败要有提示与重试**。
- **口径（第二步：老板已确认，请按此实现并在标签上写清楚）**：
  - **今日订单数**：= 当日**销售单数 + 加工单数**（**要算加工单**）；主数字显示合计，建议下方给拆分（销售 X 单 / 加工 Y 单）；
  - **销售克重**：= 当日销售单克重 **+ 加工单的补金克重**（`processing_order.store_gold_weight`，即店里卖出的金料）—— 标签写「销售克重（含加工补金）」；
  - **回收克重**：= 当日回收单克重 **+ 加工单的回收屑/剩余金克重**（`processing_order.residual_gold_weight`，即客户旧料剩余）—— 标签写「回收克重（含加工剩余金）」；
  - 所有统计都要排除撤回单（`WITHDRAWN`）与软删除会员；日期按 `Asia/Shanghai` 的"今天"。
- **定位线索**：首页 KPI 的数据来自哪个接口/字段（很可能字段名不符、时间范围参数缺失、或接口没返回这几项 → 需要后端补字段）；先确认"接口到底返回了什么"，再决定是前端取错还是后端没给。
- **验收**：造 1 张销售单 + 1 张带补金/回收屑的加工单 + 1 张回收单，首页三个数字都能对上（给出具体数字核对过程）。

## 问题 7：每进入一个页面，返回都回到首页（含「我的」子页；右划返回也一样）

- **现象**：从首页进入任意页面（加工订单、单据、消息、报表…），点左上角返回，**都跳回首页**，而不是回到上一层。**在「我的」里随便点进一个子页，右划（返回手势）也直接跳首页。**
- **期望**：按**层级**返回，**返回按钮与右划返回手势行为一致**：
  - 首页 → 加工订单列表 → 加工单详情：在详情返回 = **加工订单列表**，再返回 = 首页；
  - 首页 → 单据 → 某单据：返回 = 单据列表，再返回 = 首页；
  - 首页 → 经营报表 → 员工排行：返回 = 经营报表，再返回 = 首页；
  - **「我的」里的任一子页（设置/账号/关于/消息设置等）：右划或返回 = 回到「我的」，不是首页。**
- **定位线索**：`components/DesignHeader.vue` 的 `@back` 处理（是否写死 `router.push('/')` 或依赖不存在的 history）、`views/RoleHome.vue` 的 `section` 状态（是否每次返回都重置为 `home`/`dashboard`、「我的」子页是否也是 section 切换而非路由）、路由表 `main.js` 中同一组件复用导致 history 不增长、以及统一的返回手势实现（`App.vue` 的 touch/swipe 处理是否直接 `router.push('/')`）。
- **验收**：逐条走一遍并截图/说明：
  1. 首页 → 加工订单 → 详情 → 返回=加工列表 → 返回=首页
  2. 首页 → 单据 → 某单据 → 返回=单据列表 → 返回=首页
  3. 首页 → 经营报表 → 员工排行 → 返回=经营报表 → 返回=首页
  4. **我的 → 任意子页 → 右划=回到「我的」；点返回按钮=回到「我的」**
  5. 安卓物理返回键行为与页面按钮一致。
  **每一层都必须是"上一页"，任何情况下都不能直接跳首页。**
