# V1.0.0-rc.1 回滚说明

## 回滚触发条件

- 登录、收款或打印主流程不可用。
- 库存出现重复扣减、负库存或跨门店数据异常。
- 图片大面积不可访问、数据库迁移失败或权限越权。

## 回滚前

1. 暂停门店新增订单、入库、盘点、回收和加工操作。
2. 记录 `docker compose ps` 与 `docker compose logs --tail=300 backend`。
3. 执行 `./backup.sh`，同时备份 `data/minio`、`data/uploads` 与当前 `.env`。
4. 核对上一正式版本的安装包、镜像标签和 SHA-256。

## 服务端回滚

1. 执行 `docker compose down`。
2. 恢复上一版 `server` 目录和镜像标签，不覆盖当前数据目录与 `.env`。
3. 本版本数据库变更为兼容性新增字段时可保留数据库；若业务数据已被错误写入，先使用上线前备份恢复。
4. 执行 `docker compose up -d`，等待服务健康。
5. 验证四角色登录、库存、订单、图片、WebSocket 和打印任务后恢复营业。

## 收银端回滚

1. 先导出或确认本地待同步队列为空。
2. 卸载候选版并安装上一正式版，保留正确的 API 网关地址。
3. 验证扫码枪、收款、58/80mm 小票和 A4 质保单。

## 回滚后核对

- 核对回滚时间点前后的订单、库存流水、财务流水和图片数量。
- 对异常单据逐单登记，不通过直接修改数据库补账。
- 保留日志、备份和问题复现步骤，修复后重新生成新候选版本。
