# Android 与云部署检查报告

检查时间：2026-09-20。对象：Android 1.0.0-rc.2、本地移动端和后端源码、V1.0.0-rc.1 部署目录、线上 admin/m 域名。此次只做检查，未修改生产代码、现有发布包、服务器配置或业务数据。

## 已验证正常

- admin 域名健康接口返回 HTTP 200 与 JSON `{"status":"UP"}`；APK 来源的授权头预检返回 200。
- 上传接口的 CORS 预检允许 APK 来源；其他未允许来源请求返回 403。
- 未登录访问订单列表返回 401。
- 移动端 HTTPS 登录页可访问，移动端 HTTP 自动跳转 HTTPS。
- 当前 HTTPS 证书验证正常，证书到期时间为 2026-12-18；是否自动续签尚未核实。
- 重新运行移动端现有测试：21 文件、48 测试通过。

## 上线前优先处理

| 优先级 | 发现与证据 | 影响 | 完善方式 |
|---|---|---|---|
| 高 | admin 上传路径收到声明为 1,100,000 字节的 OPTIONS 请求时直接返回 413；此探测未发送图片或写入数据。Nginx 源配置未设置上传大小，Spring 配置也未显式设置 multipart 限制，而 UploadController 允许 5 MiB、入库压缩目标为 2 MiB。 | 一部分手机照片在进入业务接口前被拦截。 | 统一 Nginx 请求体上限、Spring 单文件/总请求上限和前端提示；例如 5 MiB 单文件、10 MiB 总请求，使用不同大小真实 JPEG 做已登录上传验收。 |
| 高 | `https://m.xinchengjinjiang.com/actuator/health` 仍返回 HTML；checkConnectivity 只检查请求是否成功，未验证 status=UP。隔离测试复现 HTML 被判在线。 | 网页版网络状态不可信；APK 使用 admin 域名，这条路径已由服务器修复。 | mobile-web 同样补精确健康检查代理；前端验证响应结构。 |
| 高 | 旧发布目录 schema.sql 中 sales_order.handover、processing_order.handover/handover_time 仍缺失；admin/mobile Nginx 源文件仍缺健康代理；mobile Dockerfile 仍用 localhost 健康探测。 | 当前服务器临时修复后，下一次全新部署或覆盖可能复发。 | 同步源建表文件、幂等升级 SQL、镜像配置与发布说明，重新生成发布清单和哈希；保留线上 nginx-live/SSL 挂载。 |

| 高 | 入库历史、待同步队列、盘点草稿使用固定 localStorage key；退出只删除 token/user/refresh-token。 | 同一手机切换员工后可能看到前一个人的草稿，待同步订单归属不清。 | 按门店和用户隔离缓存；退出提示待同步单；保留未同步数据并绑定原提交人，避免简单清空造成丢失。 |

## 后续完善

| 项目 | 发现 | 建议 |
|---|---|---|
| 在线/同步状态 | 界面用 offline 一个标记表达“在线·已同步”；WebSocket 关闭未改变独立同步状态。 | 分开接口可达、实时连接、最后同步时间，断线给出“重连中”。 |
| 长时间登录 | 前端有 refreshToken 分支，但当前 AuthController 登录仅返回 token，也未实现 refresh 路由。源码 JWT 默认 2 小时，线上通过环境变量覆盖，实际时长未读取。 | 明确会话到期策略；到期前保留草稿并提示重新登录，若需长期登录再实施完整的可撤销刷新令牌机制。 |
| WebSocket 会话 | 后端只在握手后校验 JWT；现有连接未见定期检查账号禁用或令牌过期，广播按门店而未按个人权限筛选。 | 禁用/权限调整后及时断开或重校验；按事件内容决定个人接收范围。尚未对真实账号做禁用测试。 |
| HTTPS | admin HTTP 仍返回 200 网页；m HTTP 已重定向。 | admin 同样强制跳 HTTPS；确认续签任务和证书 reload。 |
| 接口文档 | 未登录访问线上 `/v3/api-docs/` 返回 200 JSON。 | 内部系统生产环境关闭或限定访问 Swagger/API 文档。这不等于业务接口绕过鉴权。 |
| 备份 | 仓库 backup.sh 只备份 MySQL；照片在 MinIO，配置和签名在其他位置。线上备份计划及恢复结果未确认。 | 数据库、MinIO、配置/证书、APK 签名分别备份，异地存储，隔离环境恢复演练。 |
| App 更新 | 已有同签名覆盖升级说明，未实现版本检查/下载提示。 | 增加版本页、签名不变的安装包下载、版本和 SHA-256；不把签名私钥放到下载站。 |

## 验证证据与范围

临时隔离探测代码和结果保存在 runtime-logs/deployment-audit-20260920。三个探测断言用于证明现存缺陷；已从正式测试目录移除，避免将错误行为固化为正确行为。

公网请求仅用于健康、CORS、未认证访问、HTTPS 和上传大小配置检查；未使用员工密码或令牌，未生成订单、入库、会员、图片等业务数据。

实体手机实物条码识别、带账号的照片上传和管理/收银端显示、跨端改价/会员刷新、断网后重连、待收款库存占用、角色/个人权限、账号禁用等仍需要完整验收。本报告不表示整套系统无缺陷。

更正前次 APK 交付表述：已验证原生相机和本地照片读取、API 跨域连通；未完成照片上传到生产存储再回读的业务闭环。本次发现 413 正说明仍需补该验收。

建议处理顺序：上传大小和网页健康检查 → 发布包配置一致性 → 图片地址/实时连接/个人权限/草稿隔离 → 真机全流程 → 备份恢复、续签和版本更新。
