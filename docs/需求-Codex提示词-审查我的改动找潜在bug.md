## 3. 重点怀疑点（请优先查这些，别只做表面 review）

1. **时区自相矛盾**：生产**容器与 MySQL 都跑在 UTC**（`now()` = UTC），我却在移动端几处改用"本地日期"做判断 ✗ → 请逐个核对：`ProcessingOrders.vue` 的预计取货日期/超期判断、报表"今天/本月"边界、打印时间，**是否与库里的 UTC 值一致**；是否会差一天。并给出统一方案（建议：容器 `TZ=Asia/Shanghai` + MySQL `+08:00` + 历史数据 +8h，代码侧去掉双重转换）。
2. **组合支付的撤回/退款冲销**：组合支付只落一条 `pay_method='COMBINATION'` 的收款记录 ✗ → 撤回、退款、审批冲销时**是否按方式逐条处理**？团购核销单号占用、会员余额（本例不含储值）、财务流水与报表口径是否一致？请给出"组合支付 → 撤回/退款"的完整推演。
3. **幂等的所有入口**：`client_request_id` 为空的老客户端/老草稿会怎样？并发双击？断网重传 + 服务端唯一索引冲突是否被正确 catch 成幂等回放（而不是 500）？
4. **渠道语义识别是否漏点**：全仓搜索是否还有写死的 `'BALANCE' / 'CASH' / 'WECHAT' / 'COMBINATION'` 等用于**业务判断**（不只是展示）的地方？
5. **足金线规则**：全仓再扫一遍是否存在 `weight * purity * price` 形式的自算（我在 `PaymentChannelPolicy`/旧金相关改过，但可能仍有遗漏）。
6. **离线队列/草稿重放**：`processingSync` 的并发锁、失败退避、重复提交风险；`pendingProcessing` 的键位与门店/账号隔离；队列项"永久失败"时是否有出口。
7. **缓存策略副作用**：`/assets/ =404` + `index.html no-cache` 对**手机端 Service Worker 离线缓存**（`mobile/public/sw.js`）有没有副作用？离线时会不会因为 404 而白屏？
8. **统计口径一致性**：我改的"营业额含加工、件数/克重只算销售"与后端 `ReportController` 的口径、以及提成接口新增的"待取货预估"是否**同一套口径**（时间范围、撤回单排除、软删除会员）。
9. **数据范围与权限**：我改的接口/查询是否都带 `store_id`、`deleted=0`、`status<>'WITHDRAWN'`；有没有顺手放宽了权限。
10. **迁移可重复执行**：我加的列（`processing_order.settlement_remark` 等）与你的 `processing_order_item` / `processing_price_tier` 回填语句，**重复启动是否幂等**、生产 27 张老单会不会重复插子项。
