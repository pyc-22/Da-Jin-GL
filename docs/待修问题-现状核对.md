## 1. `/api/file/**` 任何人都能访问（无登录也能读文件）**[已证实]**

- **现状**：鉴权拦截器把 `/api/file/` 整个前缀放进了**免登录白名单**，因此任何人只要知道文件路径，**不用登录**就能读取（含客户照片、商品图等）。
- **证据**：`backend/src/main/java/com/dajin/system/config/AuthInterceptor.java:17` —— 白名单里包含 `path.startsWith("/api/file/")`；业务代码把客户照片路径按 `/api/file/...` 存储（`ProcessingController.java:740`、`:1662`）。

## 2. 新建员工时若未填密码，默认密码是 `admin`（明文）**[已证实]**

- **现状**：管理端「增员」接口在请求里没带 `password` 时，直接把字符串 `admin` 写进 `sys_user.password`；登录时对不以 `$2` 开头的口令走**明文比对**，因此新员工用 `admin` 即可登录。
- **证据**：`backend/src/main/java/com/dajin/system/admin/AdminController.java:173` —— `q.getOrDefault("password","admin")`。

## 3. 回收开单的幂等是"先查后插"，没有唯一键兜底 **[已证实]**

- **现状**：回收开单会用 `clientRequestId` 去 `operation_log`（module=RECYCLE、action=CREATE）**先查一遍**，查到就直接返回；但**没有**在该业务表上建 `client_request_id` 列 + 唯一索引。两个请求**同时**到达时，两次查询都会是"没查到"，随后各自插单 → 可能产生两张回收单。
- **证据**：`backend/src/main/java/com/dajin/system/recycle/RecycleController.java:31-33`。

## 5. 出入库单号用「类型 + 毫秒时间戳」生成 **[已证实]**

- **现状**：多处单号 = 前缀 + `System.currentTimeMillis()`，同一毫秒内的两笔操作可能得到**相同单号**；另有两处幂等键在客户端未传时也用毫秒兜底。

## 6. 出库审批阈值在货品成本价为 0 时形同失效 **[已证实]**

- **现状**：出库需要审批的判定金额 = `货品成本价 × 出库数量`；当成本价为 0（例如按克商品没填成本价——生产上「足金用料」之前正是这种情况）时，判定金额恒为 0，**永远小于阈值**，于是不会生成审批单。
- **证据**：`backend/src/main/java/com/dajin/system/stock/StockController.java:534-536` —— `value = coalesce(cost_price,0)*qty` 与 `limit = config("stock_out_approval_limit", 10000)` 比较；成本价问题实例见「待办与问题总览」第三节。
- **期望（老板填写）**：

## 10. 时区：服务端与数据库都跑在 UTC，界面显示比真实北京时间早 8 小时 **[已证实]**

- **现状**：生产后端容器时间 `10:47 UTC`、MySQL `now()` = UTC；手机端因做了"当 UTC 转 +08"反而显示正确，收银端直接显示原值 → 早 8 小时；报表"今天"的边界在北京时间 00:00–08:00 之间会算成前一天。
- **证据**：生产实测（服务器 `18:47 CST` / 容器 `10:47 UTC` / MySQL `now()` = `utc_timestamp()`）；详见「移动端问题清单」问题 9。

## 12. 按克商品成本价缺单位，库存金额可虚高数十倍 **[已证实]**

- **现状**：商品表单「成本价」无单位提示；库存金额口径为 `库存 × 成本价`，按克商品的库存单位是克 → 若成本价按"整件"填（生产上「足金用料」填了 45500），金额会被放大；反之填 0 则金额少算。生产已人工修正为 940 元/克（金额 ¥45,749.80）。
- **证据**：`AdminController.java:143-144`（`sum(g.stock*g.cost_price)`）；详见「移动端问题清单」问题 11。
