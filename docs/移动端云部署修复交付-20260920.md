## 升级前

1. 员工在旧 App 原账号中处理完待同步入库；还有本地草稿时留存原账号、单号、照片，避免升级后重复录入。
2. 选择暂停营业操作的时间，暂停开单、收款、入库与资料修改，留出约 10–20 分钟。
3. 确认服务器磁盘有至少 3 GB 可用空间；配置了 Docker Compose、Python3、curl、unzip。脚本需 sudo 权限。
4. 本补丁适用于当前 Compose 的 backend、mobile-web、admin-web、mysql 服务，admin-web 挂载 nginx-live 配置目录的部署。预检发现结构不符会停止。

## Ubuntu 更新步骤

**第一步：** 将 `dajin-mobile-cloud-fix-1.0.0-rc.3.zip` 和对应 `.sha256` 上传到服务器 `/home/admin/`。登录用户名若非 admin，请使用实际账号的家目录。不要删除现有部署目录。

**第二步：** 在上传目录执行校验并解压：

```bash
cd /home/admin
sha256sum -c dajin-mobile-cloud-fix-1.0.0-rc.3.zip.sha256
unzip dajin-mobile-cloud-fix-1.0.0-rc.3.zip
```

**第三步：** 从当前容器标签定位原部署目录，解决中文目录显示异常的问题：

```bash
cid=$(sudo docker ps --filter label=com.docker.compose.project=server --filter label=com.docker.compose.service=backend --format '{{.ID}}')
server_dir=$(sudo docker inspect "$cid" --format '{{index .Config.Labels "com.docker.compose.project.working_dir"}}')
printf '%s\n' "$server_dir"
sudo test -f "$server_dir/docker-compose.yml" && echo 'Deployment found'
```

若没有输出 Deployment found，保留输出进行排查，先不执行下一步。

**第四步：** 在已暂停营业操作的情况下更新：

```bash
sudo bash /home/admin/dajin-mobile-cloud-fix-1.0.0-rc.3/apply-mobile-cloud-fix.sh "$server_dir"
```

脚本先检查文件校验值，备份数据库、旧 JAR、手机静态资源、数据库初始化文件和 Nginx 配置，给旧运行镜像加回滚标签，再构建、迁移、更新后端及手机容器。保留 `.env`、Compose 覆盖配置、SSL、数据库目录和已上传照片。只执行增量 SQL，不导入初始化 schema；不会重建业务数据库。补丁会短暂中断服务。

完成时应显示 `Server patch applied. Backup: ...`，两域名健康接口均须返回 JSON UP。保留输出的备份路径。

## 失败及回滚

脚本报错后保留完整输出；错误处理会尝试恢复并重载旧 Nginx 配置，**应用文件和容器不保证自动回滚**。需要回滚时使用输出的真实 backup 路径：

```bash
sudo bash /home/admin/dajin-mobile-cloud-fix-1.0.0-rc.3/rollback-mobile-cloud-fix.sh "$server_dir" "$server_dir/backup/mobile-fix-实际时间"
```

回滚脚本使用备份镜像恢复后端、手机容器及旧文件；保留当前业务数据、照片以及新增交班字段。它不会自动恢复数据库快照，以免覆盖升级之后的业务操作。数据库快照用于另行评估后的灾难恢复。回滚后镜像使用备份标签，在查明问题之前不要直接执行常规 compose up，以免再次选中新镜像。

## 手机升级和门店验收

服务器更新成功后，把新 APK 发给一台安卓手机，直接覆盖安装；先不卸载旧版。确认“我的 → 版本”显示 rc.3。

| 验收 | 预期 |
|---|---|
| 登录与网络状态 | 正常网络接口在线、实时连接成功；断网后明确提示，恢复网络后重连。 |
| 1.1–4 MiB 真实照片上传 | 在测试单据上传，服务器保存成功，手机重开详情、管理端和收银端查看均有图片。 |
| 超过 5 MiB 照片 | 前端给出大小提示；接口返回 413；不产生已成功上传的误导状态。 |
| 连续两笔入库 | 两笔均可拍照，图片和单据各自对应，库存没有重复提交。 |
| 个人权限变更 | 管理端修改该员工权限，手机更新入口；无权限业务请求仍由后端阻断。 |
| 账号切换 | A 的新草稿在 B 中不显示；切回 A 仍能查看；A 的旧请求不退出 B。 |
| 跨端同步 | 改价、新增会员、库存变更按现有事件刷新；若实时连接中断，恢复后重新核对。 |
| 单据与交班 | 订单列表、加工单与交班字段访问正常。 |

本地验证结果：移动端 26 文件共 60 测试、后端 51 测试、部署配置 3 测试通过；H5 构建、Android 发布构建与签名验证通过；更新及回滚脚本 Bash 语法检查通过。后端上传测试使用真实嵌入式 Tomcat HTTP 请求，验证 1.1 MB 请求通过和超过 5 MiB 返回 413。Android 15 模拟器验证 rc.3 同签名覆盖安装与启动。

验证限制：本机 Docker Linux 引擎未就绪，未完整执行 Ubuntu Compose 更新和 MySQL 迁移演练；更新脚本会在服务器执行迁移、nginx -t 及健康校验。实体手机、已登录生产照片上传回读和跨端业务流程尚未验收。已有相机/扫码模拟器验证不等同于门店真机验收。
