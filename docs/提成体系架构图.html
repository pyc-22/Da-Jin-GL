打金店管理系统 · 提成体系架构图
两条相互独立的提成线：销售提成（导购 · 按月重算） ｜ 加工提成（金匠 · 按单生成与发放）
① 使用角色与入口
管理员 / 店长
管理端网页：配规则、核算、生成与发放提成、导出工资表
导购（SALES）
手机端：只看本人销售业绩与销售提成
金匠（CRAFTSMAN）
手机端：只看本人加工单与加工提成
▼
② 提成规则配置（管理端维护）
默认销售提成率
sys_config：default_commission_rate，默认 1%（0.01）
销售单结算时快照到订单，之后改率不影响旧单
加工项目提成率
processing_item 按项目设置（如饰品加工 10%、维修 15%）
开加工单时快照到 processing_order
提成规则表 commission_rule （预留）
可按 销售/加工/回收 配比例与条件 JSON，管理端可增改
当前核算引擎尚未读取其阶梯条件；回收提成也未单独核算
▼
A · 销售提成 → 导购（按月重算）
1. 触发：销售单结清
收银端全额收款 / 优惠结清（PayController，单据 0→1 已完成）；审批通过补结的单同样触发
▼
2. 快照提成率
结算时把当时默认率写入 sales_order.commission_rate_snapshot（仅写一次）
▼
3. CommissionLedger 月度重算（按"导购 × 月份"分组）
· 销售基数 = 财务流水实收：SALE 收入 − SALE_REFUND 退款
· 提成额 = Σ round（每单实收 × 该单快照率，2 位）
· 仅统计已完成单（部分收款单不计入）
· 当月 delete + insert 重算，幂等可重复执行；门店行锁防并发
▼
4. 落账：commission_record
每个导购每月一行：销售额 / 提成额 / 来源 SETTLED_ORDERS
手动入口：管理端"重新核算" POST /api/commission/calculate（管理员/店长）
B · 加工提成 → 金匠（按单生成、手动发放）
1. 触发：加工单完工 / 取货
状态 COMPLETED 或 PICKED_UP，且已分配金匠 craftsman_id
▼
2. 管理员点"生成提成"
POST /processing/commissions/generate，按单+金匠幂等（同一单不重复生成）
▼
3. 按单计算
· 提成基数 = 工费 labor_fee（不是金价）
· 提成额 = 工费 × 项目快照率 ÷ 100（四舍五入 2 位）
· 归属该单金匠
▼
4. 落账：processing_commission = 待发放 PENDING
▼
5. 管理员点"发放" → 已发放 PAID
记录 paid_at / paid_by，写操作日志 COMMISSION_PAY
▼

④ 展示、统计与全端同步
管理端网页（admin-web）
· 提成页：规则表、月度提成明细、重新核算、导出工资表 Excel
· 加工管理：加工提成列表/筛选、生成、发放、待发/已发汇总、按金匠统计
· 报表：提成总额、员工销售排行
手机端（mobile H5）
· 导购：个人业绩 / 我的销售提成（仅本人）
· 金匠：我的加工单与加工提成（仅本人）
· 管理员/店长：查看全员业绩与提成
每次核算 / 生成 / 发放后，后端经 WebSocket 广播 COMMISSION_UPDATED 与 REPORT_UPDATED，管理端、收银端、手机端自动刷新（轮询兜底）
销售提成口径：按"月"重算，基数为财务流水实收（优惠结清按实收、退款自动冲减）；未结清的部分收款单不参与；改了规则点"重新核算"即整月重建，可反复执行。
加工提成口径：基数是工费而非金价，完工后手动"生成"、再手动"发放"，全程留状态与操作日志；项目率在开单时快照，事后调价不影响旧单。
权限：规则配置、重新核算、生成与发放仅 ADMIN / MANAGER；普通员工只能查看本人数据。待建设：commission_rule 阶梯/分类条件、回收提成目前仅可配置、未参与核算。
