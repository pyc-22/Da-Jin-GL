# 手机端打包说明

更新：2026-09-23。当前移动端版本 1.0.2（100004），覆盖升级 1.0.0-rc.3。

## 实际技术与交付物

移动端是 Vue3 + Vite + vue-router 工程，现有 manifest.json、pages.json 不是完整的 uni-app 原生构建链。Android 使用 Capacitor 7 承载内置页面，ZXing 原生相机扫码，Capacitor Camera 拍照。旧文档直接用 HBuilderX 导入打包的步骤不适用于当前工程。

- 包名：com.xinchengjinjiang.mobile；名称：打金店移动端。
- 最低 Android 7.0（API 24），目标 Android 15（API 35）。
- APK：D:\xiangmu-wenjian\releases\android\dajin-mobile-1.0.2.apk。
- H5：pnpm run build:h5，输出 mobile/dist/build/h5；Android 页面输出 mobile/dist/build/android。
- 业务数据库仍在服务器，APK 需要联网；iPhone 继续使用 HTTPS 网页版，此次未生成 IPA。

## 服务器

mobile/.env.android 固定 API=https://admin.xinchengjinjiang.com、WebSocket=wss://admin.xinchengjinjiang.com。
Capacitor 本地页面来源为 https://m.xinchengjinjiang.com，与现有 HTTP/WebSocket CORS 白名单一致。没有设置远程 server.url，页面从安装包读取。只允许 HTTPS，不放开混合内容或证书错误。更换服务器域名需同时调整构建变量、Capacitor 来源及后端白名单后重新打包。

## 本机重新构建

工具：Node.js/pnpm、JDK 21、Android SDK（platform-tools、platform android-35、build-tools 35.0.0；Gradle 还会下载 34.0.0）、Gradle 8.11.1。

```powershell
cd D:\xiangmu-wenjian\dajin-system\mobile
$env:JAVA_HOME = 'D:\dajin-android-tools\java\jdk-21.0.12.1+1'
$env:ANDROID_HOME = 'D:\dajin-android-tools\sdk'
$env:DAJIN_GRADLE = 'D:\dajin-android-tools\gradle-8.11.1\bin\gradle.bat'
pnpm install --frozen-lockfile
pnpm test
.\scripts\build-android.ps1
```

脚本执行网页构建、cap sync、assembleRelease、zipalign、apksigner，输出 APK、SHA-256 和签名验证报告。当前网络下载 Gradle 时遇到重定向域名解析问题，已从镜像获取并与官方 SHA-256 比对一致。

## 签名和更新

发布签名独立于调试签名，位于 C:\Users\0.0\.dajin\android-signing，访问权限限制为当前用户和 SYSTEM。里面的证书及 signing.json 密码由店主保管、私密离线备份，不发给员工，不放到公开下载目录。

第一次初始化才使用 -InitializeSigning。以后要求恢复同一套签名；缺失时脚本停止。升级时增加 android/app/build.gradle 的 versionCode、更新 versionName，再用同一证书构建。员工直接安装新版 APK 覆盖更新，不先卸载，以保留登录及待同步草稿。本版未实现自动下载更新。

## 功能行为

- 开单、货品搜索、入库、盘点使用原生相机实时识别二维码和常见条码；保留主动选择的手动输入。
- 扫码结果继续走现有货品/单件唯一编号解析，取消或权限拒绝不产生伪条码。
- 入库照片、货品照片、加工来料/称重照片接原生拍照，再走现有压缩、上传、订单关联。
- 相机按需请求权限；回访打开系统拨号页，不申请直接拨号或通讯录权限。
- 登录沿用持久化存储；返回键返回上一页，首页返回则最小化。
- Android 15 加入系统栏边距适配，界面固定浅色。
- 加工单保留“送收银端打印”，移动端不新增直接打印入口。
- 前台角色仍按现有权限使用电脑收银端。

## 员工安装

先应用配套服务器补丁，再安装 rc.3 APK。仅安装 APK 不会改变服务器照片上传限制。服务器应用前需暂停开单、收款、入库等写入操作，备份后更新。

升级前请在旧版原账号内完成待同步入库。rc.2 的历史本地草稿没有可靠的账号归属信息；rc.3 保留原始缓存并提示存在旧数据，但不会自动把它归给当前登录人。升级前还有待处理草稿时，先留存原账号、单号和照片，再核对服务器记录，避免重复入库。新版本缓存按门店和账号分别保存。

将 APK 传到安卓手机，通过系统文件管理器打开，按系统提示允许该来源安装，完成后可关闭该来源安装权限。第一次扫码/拍照允许相机权限，用现有店长或销售账号登录。

先在一台手机试用：登录 → 扫一件商品 → 返回再扫另一件 → 连续入库拍照 → 检查照片 → 会员/报表 → 加工单送收银打印 → 重开 App。需要写入订单或库存的步骤，使用门店标记的测试单据并按业务流程处理。
