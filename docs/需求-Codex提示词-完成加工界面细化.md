# 收银端「完成加工登记」界面细化（交给 Codex）

> 用法：整段复制给 Codex。每条只有「现状 + 期望」，期望是老板的要求。
> 适用范围：**收银端**（`front-pc`）的「完成加工登记」弹窗（一单多件之后，这张表要同时管 1~N 个子项）。
> 规则：只改必要文件；每条给「改了哪些文件 + 怎么验证」；**不要部署、不要动生产、不要 push**；四套测试全绿（后端 217 / 管理端 63 / 手机端 180 / 收银端 84）。

## 1. 逐件只让填"计费克重"，看不到每件的项目、单价和算出来的工费

- **现状**：多件单在"③ 称重与损耗"里，每个子项**只有一个输入框**：`项目名 · 计费克重(g)`；看不到这件是**按件还是按克**、**数量**、**单价**，也看不到**这件工费算出来多少、命中哪一档**。
- **期望**：每个子项那一行改成能看清的小卡片，至少显示：
  - **项目名 + 计价方式（按件/按克）+ 数量**；
  - **该件的工费**（实时算出来，并显示算式，例如 `25.00 元/g × 12.345g = 308.63`；一口价档就显示 `一口价 200.00`；命中档位写清，如 `>10g 档 30 元/g`）；
  - 输入框只保留**该件需要填的东西**：按克项目填"计费克重"，**按件项目不要显示"计费克重"**（它按数量计价）。

## 2. 看不到"本单工费合计"，没法当场跟客户对账

- **现状**：改了各件的克重/价格，界面上**没有工费合计**，也没有应收合计；只有提交之后才知道。
- **期望**：界面固定显示一块**小结**：各件工费 → **工费合计** → 加上补金金额 → **本单应收合计**；任何输入变化都实时跟着变（只做预览，最终以后端结算为准）。

## 3. 回收屑两种选择都看不到"多少克、抵多少钱"

- **现状**：只有选「留店抵扣工费」时才显示"回收屑 2.000g / 抵扣 -¥xxx"；选「客户带走」什么都不显示。
- **期望**：**两种选择都显示**算出来的回收屑克重（客户带走时写"客户带走，不计入抵扣"），让柜面一眼知道这单有没有剩余金、多少克。

## 4. 整单缺少"来料 → 成品"的一行小结

- **现状**：来料克重/成色、融后金重、补金、成品实重/成色、损耗分散在①②③，需要自己心算核对。
- **期望**：在「④ 回收屑」上方加一行**只读小结**：`来料 X g（折重 Y g）｜融后 Z g｜补金 A g｜成品 B g｜损耗 C g｜回收屑 D g`，数字随输入实时更新（不改变任何计算口径，只是显示）。

## 5. 收银端看不到这单的"子项清单"是否和开单时一致

- **现状**：完成加工时只看得到项目名（`项目名 · 计费克重`），看不到**开单时的数量/单价快照**，也没法确认"是不是这几件"。
- **期望**：每个子项显示**开单时的快照**：项目名、数量、计价方式、单价/工费快照；如果客户临时改了件数，柜面能一眼发现并提示去管理端/手机端改单（加工中不允许在这里改子项）。

  **在老板明确回复前不要做这条。**
